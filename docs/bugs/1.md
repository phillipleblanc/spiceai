Bug Report: UnionProjectionPushdownOptimizer - Schema change during transform_down breaks parent nodes
Error

DataFusionError(Context("UnionProjectionPushdownOptimizer", ArrowError(SchemaError("project index 14 out of bounds, max field 14"), Some(""))))
Root Cause
When the optimizer finds an eligible projection, it returns Transformed::yes(projection.input()) (line 270), removing the projection from the tree during the first transform_down pass. This changes the subtree's schema: the removed projection's input schema is now exposed instead of its output schema.

During the same transform_down traversal, after a child is replaced, DataFusion's map_children rebuilds parent nodes via with_new_children. ProjectionExec is the primary offender: it reconstructs itself with its original expressions (bound to the old child's output schema) but the new child (with different schema). When the removed projection narrowed or reordered columns, the parent projection's column indices become invalid → Schema::project() fails with "index out of bounds".

Other parent nodes with column-indexed expressions (e.g., FilterExec) could also become invalid from the schema change, though they'd fail differently.

Why existing checks don't catch this
The schema validation at lines 161-186 validates union leaf schemas before pushdown. The bug occurs when an ancestor node is rebuilt against an incompatible intermediate schema during traversal—a case the existing checks don't cover.

Fix Directions
Use Transformed::complete(projection.input()) when pruning, so traversal stops immediately and parents aren't rebuilt against the temporary schema.

Two-phase approach: Don't alter the tree during the first pass. Collect all transformations, then apply them atomically so parent rebuilds see stable final schemas.

Use transform_up: Process children first so ancestor rebuilds always see stable schemas from already-transformed descendants.

Preserve schema for ancestors: If keeping top-down, use a placeholder node or defer removal until the final rewrite pass to avoid exposing intermediate schemas to parent rebuilds.
